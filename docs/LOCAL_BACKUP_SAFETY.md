# 本地快照备份安全修复

日期：2026-11-03。验证基线：`f0cf60ca5829b05635ef77ad14f46d1a87a58fbf`。

## 修复范围

本次只修改前端持久化模块 `jsonFileStore.ts`，新增合成回归测试；不修改配置、Tauri 权限、真实数据或部署。

原先恢复函数读取 backup 后调用普通保存，普通保存先用当前主快照覆盖 backup，再写恢复后的主快照。若主快照已经损坏，最后一次主写入又失败，就可能同时失去可读的主、备两份数据。

现在：

1. 恢复先校验备份、迁移并准备可序列化的数据，只写主快照，不轮换或修改恢复来源 backup。
2. 普通保存先检查现有主快照，再把通过检查的原始字节存为 backup。检测到 JSON 损坏、集合形状错误、版本不支持、现有业务校验失败或项目归属不符时拒写，保持存储原样。
3. 本地 scoped 主、备快照必须显式属于请求的项目。可识别为其他项目的恢复目标也拒绝覆盖；损坏而无法解析的目标仍可用本项目备份恢复。
4. 序列化在任何备份轮换之前完成，避免序列化失败后已修改 backup。
5. 同一 JS 实例内，同项目的加载、保存、恢复、删除串行；恢复读取 backup 也位于队列内。单次操作失败不会堵住后续队列，不同项目独立排队。

历史无项目范围的浏览器 legacy 迁移保持原行为：迁移成功后清理原 legacy 键，写入失败则保留原文。本次没有新增历史清理或自动恢复操作。普通保存拒写损坏主快照后，需要使用独立恢复路径，不能把自动读取 backup 当成已修好主快照。

## 未解决的边界

- 此仓库仍是未通过完整构建的迁移基线。SettingsPage 使用的 `restoreBackup` 还未在 provider/repository 中接通，本次不补界面或冒充完整可用桌面功能。既有缺口见 `MIGRATION.md`。
- 队列不是跨标签页、跨窗口或跨进程锁，也不提供跨调用的乐观并发事务；外部写入仍可能竞争。
- Tauri 当前能力不含 rename，本次不扩大权限、不宣称文件原子替换或断电安全。恢复主写失败可能截断主文件，但不会触碰恢复来源 backup。普通备份写入若发生部分失败，主快照不会继续写入，但旧备份的字节完整性仍无法由本次修改保证。
- 原始结构检查和现有业务校验不是所有字段的完整运行时类型验证。受支持的旧版本仍会进行兼容迁移，不能宣传能识别任意损坏。
- 未运行真实浏览器配额、Windows/Tauri 磁盘故障、完整界面端到端或安装包验收，未部署。
